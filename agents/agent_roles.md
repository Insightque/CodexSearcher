# CodexSearcher 에이전트 역할 정의

## 1) Discovery Agent (탐색 에이전트)

- 입력: 검색 조건(예: 키워드, 기간, 최소 스타), 최신성 우선순위
- 출력: 후보 레포지토리 원본 목록
  - `repo`, `stars`, `description`, `url`, `created`, `updated`
- 책임:
  - GitHub Search 기반으로 최신 Codex 관련 레포지토리 탐색
  - `created`, `updated`, `stargazers_count` 기준으로 정렬

## 2) Analysis Agent (분석 에이전트, 생산성 중심)

- 입력: Candidate list(Discovery Agent 결과)
- 출력: 분석 포인트
  - 실무 생산성 향상 가능성
  - 도입 난이도/운영 리스크
- 책임:
  - 스타 수, 설명 키워드 기반 가중치 분석
  - 실제 업무에서 바로 쓸 수 있는 시나리오 제시
  - 생산성 우선 후보 선별

## 3) Daily App Scout Agent (일상 앱 스카우트 에이전트)

- 입력: Candidate list(Discovery Agent 결과)
- 출력: 분석 포인트
  - 일상생활에서 바로 써먹을 수 있는 앱형 아이디어 후보
  - 재미/몰입 요소가 있는 사용성 포인트
  - 생활 습관/취미/학습/금융/건강/가족 관리에 대한 활용성
- 책임:
  - 레포지토리 설명/토픽에서 일상 활용성 점수화
  - 생산성 분석(에이전트2)와 분리해 생활형 후보 우선순위 제안
  - 사용자 요청 시 Agent 1와 협업해 최종 제안 후보를 정리

## 4) Validation Agent (검토/최종 제안 에이전트)

- 입력: 탐색+분석(에이전트2) + 일상앱 스카우트(에이전트3) 결과
- 출력: 최종 후보 필터링 및 활용 제안 리포트
  - `pass` / `review` / `hold`
  - 추천/보류 근거
  - 바로 적용 가능한 실험 계획
- 책임:
  - 사용자가 제시한 목적(실무/일상)과 맞는지 판별
  - **일상앱 스카우트 항목은 설명 기반으로 ‘생활 적용성(직접 사용성/진입장벽/지속성)’을 별도 점검**
  - 검토 대상이 생활형일 경우 즉시 반영 여부(PASS/REVIEW/HOLD)까지 제시
  - 실행 우선순위 확정

## 운영 방식

- `Orchestrator`는 사용자 요청마다 쿼리 조건을 갱신하고, 위 4개 역할 출력을 하나의 Markdown 레포트로 합칩니다.
- **일상 앱/재미형 요청**이 들어오면 `Agent 1 + Agent 3 + Agent 4`가 협업하여 후보를 선별하고, `Agent 4`의 판단을 최우선으로 반영해 `Agent 4`가 최종 제안 섹션에 제안합니다.
- 보고서에는 `pass/review/hold` 외에 **일상 앱 우선순위** 섹션을 남기며, 각 레포마다 `요약/목적/일상 적용성`이 보이도록 기록합니다.
- 모든 보고서 업데이트는 `reports/` 폴더에 날짜 기반 파일로 누적합니다.
- 민감 정보(토큰/키) 저장 금지.
