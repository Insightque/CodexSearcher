# CodexSearcher 에이전트 역할 정의

## 1) Discovery Agent (탐색 에이전트)

- 입력: 검색 조건(예: 키워드, 기간, 최소 스타), 최신성 우선순위
- 출력: 후보 레포지토리 원본 목록
  - `repo`, `stars`, `description`, `url`, `created`, `updated`
  - `purpose`, `role_statement`, `indie_app_level`
- 책임:
  - GitHub Search 기반으로 최신 Codex 레포지토리 탐색
  - `created`, `updated`, `stargazers_count` 기준 정렬
  - **독립형 앱 후보 신호 수집**: `mobile/web/desktop/app/ui/chat/voice/dashboard` 등으로 시작/운영 가능한 리포 형태인지 판별용 메타를 함께 전달

## 2) Analysis Agent (분석 에이전트, 생산성 중심)

- 입력: Candidate list(Discovery Agent 결과)
- 출력: 분석 포인트
  - 실무 생산성 향상 가능성
  - 도입 난이도/운영 리스크
- 책임:
  - 스타 수, 설명 키워드 기반 가중치 분석
  - 실제 업무에서 바로 쓸 수 있는 시나리오 제시
  - 생산성 우선 후보 선별

## 3) Daily App Scout Agent (일상 앱 스카우트 에이전트)

- 입력: Candidate list(Discovery Agent 결과)
- 출력: 분석 포인트
  - 일상생활에서 바로 써먹을 수 있는 앱형 후보
  - 재미/몰입/유지성 포인트
  - 생활 습관/취미/학습/금융/건강/가족관리 활용성
- 책임:
  - 설명/목적 기반으로 **독립형 앱성** 점수화
  - 사용 즉시 앱 형태인지, 진입 장벽은 어떤지 분류
  - `조건부/미적합` 후보도 이유와 함께 보존하여 Agent 4 재심사에 전달

## 4) Validation Agent (검토/최종 제안 에이전트)

- 입력: 탐색+분석(에이전트2) + 일상앱 스카우트(에이전트3) 결과
- 출력: 최종 후보 필터링 및 활용 제안 리포트
  - `pass` / `review` / `hold`
  - 추천/보류 근거
  - 바로 적용 가능한 실험 계획
- 책임:
  - 사용자가 제시한 목적(실무/일상)과 맞는지 판별
  - **일상앱 스카우트 항목은 ‘독립형 앱 적합도’와 ‘일상 적용성’(직접 사용성, 진입장벽, 유지성)으로 재심사**
  - PASS/REVIEW/HOLD 재분류 후 최종 제안 작성
  - 실행 우선순위 확정

## 운영 방식

- `Orchestrator`는 사용자 요청마다 쿼리 조건을 갱신하고, 위 4개 역할 출력을 하나의 Markdown 레포트로 합칩니다.
- **일상 앱/재미형 요청**이 들어오면 `Agent 1 + Agent 3 + Agent 4`가 협업해 후보를 선별하고, Agent 4의 판단을 최우선으로 반영합니다.
- 보고서에는 각 레포를 링크 없이도 이해할 수 있게 `목적`, `역할(기능)`, `독립형 앱성`, `일상 적용성`을 항상 남깁니다.
- `Agent 3`는 생산성 후보와 독립적으로, 순수 앱 사용 관점의 후보군을 별도 라우팅합니다.
- 모든 보고서 업데이트는 `reports/` 폴더에 날짜 기반 파일로 누적합니다.
- 민감 정보(토큰/키) 저장 금지.
